# Consumer workflow and review status

The user wants a readable tutorial, with optional narration/system sound and a shareable video. The normal path is **choose source → choose sound → Start → trim/focus → Export**. The existing Record/Edit/Settings navigation is retained because sustained editing needs a real window; this is not a background-only utility suited to a tray menu. No new tray surface or theme editor is added.

The 0.2 source revision separates sound choices from storage fields. Microphone and System sound are explicit opt-ins with a clear silent state. The generated filename and existing frame-rate default remove mandatory decisions; overrides live under Filename and frame rate. Source-specific cautions appear only for the relevant mode. Starting/recording/paused/finalizing state remains visible in the header while navigating; Pause becomes available after the first completed frame. Stop appears in the header outside Record, avoiding duplicate controls on the recording screen.

MP4 is the default export. AVI is explicitly labeled silent. Audio settings appear only when they can affect the export, and gain controls only for recorded tracks under Adjust mix. Manual zoom timing/focus lives in a collapsed specialist area; automatic zoom remains one checkbox. The selected format and output extension must agree. These changes preserve the existing media/settings formats and all editing capabilities.

`src/theme.rs` supplies reusable background/surface/text/border/accent/status roles, a 22/15/13 point type scale and an 8 point spacing rhythm. Teal marks the primary action; amber/red/green have stable status meanings accompanied by text. The palette is source-defined; it has not been visually approved from a rendered screenshot.

Applied skills: `product-design`, `rust-performance` (including its pre-computer-use gate), and `github-release-conventions`. Static review now uses a bounded, genuinely headless render mode in the packaged EXE. It calls the same `RecorderApp::show`, theme and egui 0.37 fonts/layout as the normal window, and rasterizes their numeric meshes with a CPU fallback. It never calls GUI construction, normal startup/preferences/update logic or device capture. Six application-generated PNGs at default/minimum sizes and 100%/150% scale were opened and inspected; they are not UI mockups or desktop screenshots.

That review exposed and fixed four concrete defects: Export disappeared below the minimum-size viewport, errors were below the fold, the settings path field used a narrow fixed width, and the Start button's glyph was missing. Record/Export actions and status now remain in a footer outside the scrolling content; errors appear above it; the path spans available width; the missing glyph was removed. Capture assertions check actual primary button rectangles against each viewport. See [the evidence](RENDER_REVIEW.md) and README images.

The production presenter remains Glow/OpenGL. Its rasterization/presentation parity, native chrome, keyboard/accessibility behavior, actual DPI integration and idle/hidden/restore measurements remain unverified. Headless PNGs establish layout/appearance within the stated fallback scope; they do not pass the normal rendering/load gate.

Before a future authorized normal-window review: inspect the exact packaged renderer/scheduling and use an isolated bounded diagnostic launch with frame/CPU measurements. Compare native-presenter output against the checked CPU images, and extend coverage to 200% OS scaling, focus/keyboard traversal and expanded states. Verify idle and minimized windows stop rendering separately. The existing OpenGL presenter is documented, not relabeled as CPU rendering.
