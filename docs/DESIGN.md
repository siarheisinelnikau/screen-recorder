# Consumer workflow and review status

The user wants a readable tutorial, with optional narration/system sound and a shareable video. The normal path is **choose source → choose sound → Start → trim/focus → Export**. The existing Record/Edit/Settings navigation is retained because sustained editing needs a real window; this is not a background-only utility suited to a tray menu. No new tray surface or theme editor is added.

The final 0.2 revision uses labeled vector navigation, neutral switch tiles for sound, native folder/project pickers on explicit actions, and Clean/Guided/Focus editor presets. All individual effects remain under Customize effects; sound levels and zoom timing expand separately. Technical implementation/support text is confined to About and project documentation. The source revision separates sound choices from storage fields. Microphone and System sound are explicit opt-ins with a clear silent state. The generated filename and existing frame-rate default remove mandatory decisions; overrides live under Filename and quality. Source-specific cautions appear only for the relevant mode. Starting/recording/paused/finalizing state remains visible in the header while navigating; Pause becomes available after the first completed frame. Stop appears in the header outside Record, avoiding duplicate controls on the recording screen.

MP4 is the default export. AVI is explicitly labeled silent. Audio settings appear only when they can affect the export, and gain controls only for recorded tracks under Sound levels. Manual zoom timing/focus lives in a collapsed specialist area; automatic zoom remains a single switch under Customize effects. The selected format and output extension must agree. These changes preserve the existing media/settings formats and all editing capabilities.

`src/theme.rs` supplies reusable background/surface/text/border/accent/status roles, a 26/15/13 point type scale and an 8 point spacing rhythm. A cool neutral background, white panels, graphite text and a single blue primary action replace the previous dark/teal palette. Amber/red/green retain status meanings accompanied by text. Selected tabs use a pale blue surface; primary buttons use explicit white text. Solid dark scroll handles and a dedicated slider track avoid white-on-white controls. The new palette is checked from actual rendered PNGs, not color constants alone.

Applied skills: `product-design`, `rust-performance` (including its pre-computer-use gate), and `github-release-conventions`. Static review now uses a bounded, genuinely headless render mode in the packaged EXE. It calls the same `RecorderApp::show`, theme and egui 0.37 fonts/layout as the normal window, and rasterizes their numeric meshes with the production CPU rasterizer. It never calls GUI construction, normal startup/preferences/update logic or device capture. Six application-generated PNGs at default/minimum sizes and 100%/150% scale were opened and inspected; they are not UI mockups or desktop screenshots.

That review exposed and fixed four concrete defects: Export disappeared below the minimum-size viewport, errors were below the fold, the settings path field used a narrow fixed width, and the Start button's glyph was missing. Record/Export actions and status now remain in a footer outside the scrolling content; errors appear above it; the path spans available width; the missing glyph was removed. Capture assertions check actual primary button rectangles against each viewport. See [the evidence](RENDER_REVIEW.md) and README images.

The main window now uses the same CPU rasterizer and a Win32 GDI presenter, following system-wide freezing reported during the old Glow diagnostic. Native load/restore evidence is recorded separately in [RENDER_PERFORMANCE.md](RENDER_PERFORMANCE.md). Static PNGs do not certify native chrome, keyboard/accessibility behavior or actual mixed-monitor DPI integration. Continue coverage of 200% OS scaling, focus/keyboard traversal and expanded states before public release. The original application mark is embedded as a native multi-size executable resource and assigned to the winit window. Resource rendering passed; Explorer/taskbar cache appearance still needs an OS integration review.
